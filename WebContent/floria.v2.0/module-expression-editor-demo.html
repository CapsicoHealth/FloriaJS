FloriaExpressionEditor

Two independent editor instances demonstrating the component's configurable vocabulary (vars + functions). They share the same JSON tree shape and the same tautology/contradiction analyzer — only the configuration differs. Each instance's own Editor / Preview tabs (built into the component itself — see FloriaExpressionEditor.render()) are the only UI needed to build and review the expression; nothing extra is wired up here in the demo page. Instance 1 also opts into the optional JSON tab (showTabJSON:true, off by default) to show the raw tree.

Instance 1 — Medical Code Filter (Cohort Designer)

Replicates the _anchorCodesTree vocabulary from COHORT_MARTS_DATA.FindJourneys3. Variables: DxPrimary, DxSecondaries, DxAll, CptHcpcs, Drg, PrcPrimary, PrcSecondaries, PrcAll. Functions: like, in. Each variable is backed by a real FloriaFactories.PickerRegistry Picker (DxCode/HCPCSCode/DrgCode/ PrcCode) instead of free-typed values, and a descriptionLookup handler is wired up so the Preview tab shows each code's human-readable description (bulk-fetched once, then cached for the lifetime of this editor instance) instead of opaque codes — switch to the Preview tab to see it in action.

Instance 2 — Text Matching (Agentic Test Cases)

Replicates the test-case JSON from the Agentic backend. Variables: txt. Functions: any, all, none. Pre-loaded with a sample tree for immediate visual feedback.

Both editors share the same core model/validator/tautology-detector. Only vars and functions differ between them.
